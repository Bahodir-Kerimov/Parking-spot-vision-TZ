## 1. Назначение и цели проекта
Система предназначена для автоматического определения занятости парковочных мест на уличной улично-дорожной сети города на основе видеопотоков и/или видеофайлов. Цели:
- Повышение информированности водителей о доступных местах в реальном времени.
- Снижение времени поиска парковки и транспортной нагрузки.
- Предоставление аналитики городской администрации и операторам парковок.

### 1.1. Область применения
Муниципальные улицы, придорожные парковочные карманы, площади перед ТЦ, кампусы. Варианты источников данных: уличные IP‑камеры, видеорегистраторы, заранее записанные видеофайлы.

### 1.2. Термины и сокращения
- **CV** — Computer Vision (компьютерное зрение).
- **YOLOv12** — одномоментная детекция объектов (state‑of‑the‑art).  
- **mAP@0.5 / mAP@0.5:0.95** — метрики качества детекции.  
- **IoU** — пересечение над объединением.  
- **API** — программный интерфейс приложения.

## 2. Требования к функциям (функциональные требования)
F1. Загрузка видеопотока (RTSP/HTTP) и/или видеофайла (MP4/MOV).  
F2. Автоматическая детекция автомобилей/мото/грузовых на кадрах.  
F3. Определение статуса парковочных мест: «свободно», «занято», «неопределено».  
F4. Конфигурирование зон парковки (ручная разметка полигонов на кадре).  
F5. Публикация статуса по улицам/зонам на веб‑сайте для пользователей.  
F6. Панель администратора: управление камерами, зонами, моделями, ролями.  
F7. Хранение истории статусов и отчёты (загрузка CSV/PNG).  
F8. REST API для интеграций (получение статуса, метаданных, аналитики).  
F9. Аутентификация и роли (гость, пользователь, оператор, админ).  
F10. Журналирование событий и экспорт логов.

### 4.1. Публичная часть
- Главная: выбор города/улицы → карта/список зон с цветовой индикацией.  
- Карточка улицы/зоны: количество **свободно/занято**, мини‑видеопретью, обновление в реальном времени (WebSocket/SSE).

- Отчёты: запрос агрегатов по интервалам, экспорт CSV/PNG.

### 4.3. UI/UX общие

## 6. Архитектура: подсистемы и модули
### 6.1. Обзор
- **ingest** — захват видеопотока/файла, декодирование, буферизация.  
- **detector** — инференс YOLOv12 (N/S/M по ресурсу), трекинг (ByteTrack/OC‑SORT).  
- **parking‑logic** — сопоставление детекций с полигонами мест, статус.  
- **api** — REST/WS для сайта и интеграций.  
- **web** — публичный сайт и админ‑панель (Flask/Jinja2 или FastAPI + шаблоны).  
- **storage** — БД (PostgreSQL), файлы (minio/S3 или локально), кэш (Redis).  
- **scheduler** — фоновые задачи, архивирование, ретраи.  
- **monitoring** — метрики/логи/алерты.

### 6.2. Интерфейсы между модулями (пайплайн)
`ingest → detector → parking‑logic → api/storage → web`  
- Формат кадра: numpy RGB/BGR, или JPEG/PNG для предпросмотра.  
- События статусов публикуются в Redis Pub/Sub или WS‑шину.  
- В БД хранится история: `{spot_id, status, ts, source_cam, confidence}`.

## 7. Модели и алгоритмы ИИ
- **Детекция:** YOLOv12 (Ultralytics) — классы: car, bus, truck, motorcycle, bicycle.  
- **Трекинг:** ByteTrack/OC‑SORT для устойчивости статуса во времени.  
- **Логика статуса:** геометрическое пересечение bbox с полигоном места (IoU/overlap ≥ T), гистерезис по времени для устранения дрожания.  
- **Опционально:** сегментация парковочных мест (Segment Anything/обучаемая сегментация) для автоматической первичной разметки зон.

Параметры инференса (по умолчанию): `img=1280`, `conf=0.4`, `iou=0.5`, `agnostic_nms=True`.  
Поддержка аппаратного ускорения: CUDA/cuDNN; на CPU — OpenVINO (опц.).

## 8. Обучение и данные
### 8.1. Требования к датасету
- Источники: городские улицы (включая Астрахань), разное время суток/погоды.  
- Аннотации в формате YOLO: `class x_center y_center width height` (нормированные).  
- Разметка: минимум 3 000 кадров, ≥ 30 000 объектов; валидация 15%, тест 15%.  
- Баланс: различные перспективы, плотности трафика, типы ТС.  
- Лицензии: соблюдение прав на видео, деперсонализация номеров/лиц при публикации.

### 8.2. Процедура обучения
- Аугментации: HSV, flip, mosaic/mixup (умеренно), blur/gaussian noise (ночь/дождь).  
- Гиперпараметры (пример): `epochs=100`, `batch=16`, `lr0=0.01`, `lrf=0.1`.  
- Валидация по эпохам, сохранение лучшей модели по `mAP@0.5:0.95` (val).  
- Логи обучения: TensorBoard/Weights & Biases (опц.).

### 8.3. Управление версиями данных/моделей
- DVC (или Git LFS) для датасетов; хранение артефактов в `models/`.  
- Семантическое версионирование весов: `yolov12-psv-<date>-vMAJOR.MINOR.patch.pt`.

## 9. Валидация и тестирование
- **Метрики детекции:** Precision, Recall, mAP@0.5 и mAP@0.5:0.95.  
- **Метрики статуса мест:** точность статуса (accuracy) ≥ 95% на тест‑сценах.  
- **Нагрузочное тестирование:** ≥ N одновременных потоков (N определяется ресурсами стенда), латентность публикации ≤ 5 с.  
- **Тест‑кейсы UI:** корректное обновление, фильтры, доступность на мобильных.  
- **Интеграционные тесты API:** контрактные тесты (OpenAPI), негативные сценарии.  
- **UAT/Приёмка:** демонстрация на 2–3 улицах, ≈ 40+ парковочных мест, отчёт за 7 дней.

## 12. API (черновая спецификация)
- `GET /api/v1/streets` — список улиц/зон.  
- `GET /api/v1/streets/{id}/status` — агрегаты статусов.  
- `GET /api/v1/spots/{id}` — статус конкретного места.  
- `POST /api/v1/cameras/test` — верификация RTSP.  
- `WS /ws/status` — поток статусов в реальном времени.  
Ответы — JSON; схема документируется в OpenAPI (`/docs`).
